# PS81 requirement matrix

| Requirement | Status | Repository evidence / gap |
|---|---|---|
| Karnataka-only scope | Implemented | Statewide master and IMD tables cover 31 Karnataka districts; geometry-driven operational sampling exists. |
| Physical NWP source | Implemented | GFS and IFS HRES are configured through Open-Meteo. |
| Genuine ensemble source | Partial | NOAA GEFS 0.25° ensemble mean and spread are ingested as source class `ensemble`, independently quality-checked and exported. It is `display_only_not_in_locked_blend`; historical coverage is insufficient for a locked four-source skill claim, and spread is not presented as probability. |
| AI forecast source | Implemented | ECMWF AIFS is configured as `ecmwf_aifs025_single`. |
| XGBoost adaptive blending | Implemented for locked rainfall Day 1 | Artifact `2e070898b34c589b` is frozen and loaded operationally. The untouched May–August 2026 evaluation has 3,749 paired rows: XGBoost wins overall MAE (3.939 mm); AIFS wins RMSE, absolute bias and 50 mm heavy-rain CSI. Days 2–6 remain named equal-weight baselines. |
| Region adaptation | Partial | The locked Day-1 XGBoost feature schema includes district and Karnataka-region one-hot features, and operational inverse-MAE fallback can pool within a division. A learned regional effect is possible but has not been isolated or verified with region-stratified skill tests. |
| Season adaptation | Partial | The locked Day-1 XGBoost schema includes cyclic month features (`month_sin`, `month_cos`). No season-stratified held-out skill analysis or separately validated seasonal model exists. |
| Lead adaptation | Partial | Storage, history lookup and blending are lead-specific for Days 1-6; checked-in historical skill is Day 1 only, leaving other leads cold-start. |
| Weather-regime adaptation | Blocked | No regime definition, classifier, feature or regime-stratified verification. |
| Rainfall | Implemented | District 24-hour precipitation ingestion, blending, archival and verification exist. |
| Temperature | Partial | GFS, IFS HRES and AIFS hourly `temperature_2m` are unit-checked and aggregated to 24-hour district Tmax/Tmin. Bengaluru SYNOP point verification retains 4,264 full-availability GFS/AIFS pairs and 2,427 IFS HRES pairs; the common three-source denominator is 2,427 timestamps across 319 days. Exact historical issue time remains unverified, this is not statewide district truth, and no temperature XGBoost model is trained. |
| Wind | Partial | GFS, IFS HRES and AIFS hourly `wind_speed_10m` are unit-checked and aggregated to district daily maxima; direction uses circular/vector means. Bengaluru SYNOP point verification retains 4,283 full-availability GFS/AIFS pairs and 2,477 IFS HRES pairs; the common denominator is 2,477 timestamps across 324 days. SYNOP measurement height and exact historical issue time remain unverified, gust remains excluded, and no wind XGBoost model is trained. |
| Extreme guidance | Partial | Rainfall categories and deterministic threshold scores at 1/10/25/50 mm exist; no calibrated exceedance probability, ensemble-tail guidance, return-period framing or alert contract. |
| Maps | Implemented for current deterministic products | The React map consumes the latest export, exposes date/lead/variable/source selectors, and displays the actual available-district count. Statewide cycle `bc5f2a5972e54e5da32d11f893c6b229` supplies all 31 districts; absent values remain explicitly unavailable. |
| Verification | Partial | Rainfall MAE/RMSE/bias and legacy event metrics exist with availability-time controls. Resumable station-requested verification over Bengaluru's 554-day SYNOP period produced 21,998 temperature/wind pairs; returned-grid distances and archive gaps are retained. Exact historical issue time remains unverified under the `previous_day1` product, SYNOP wind measurement height is undocumented, and these remain point observations rather than statewide district truth. No probabilistic, regime, or full multi-lead verification exists. |
| Routine operation | Partial | `routine` is a thin CLI wrapper with config/artifact/geography preflight, IST-slot duplicate prevention, one-cycle issue/export, availability-tolerant IMD ingestion, eligible-cycle evaluation and append-only JSONL health logging. Windows Task Scheduler setup is documented but intentionally not registered. External alerting, exact upstream run identity and Days 2–6 skill history remain pending. |
